# Интеграция HSK-предложений с аудио носителя (вместо Tatoeba)

## Данные
- `hsk_audio/hsk-audio-hsk{1..6}/hsk{N}-XXXX.mp3` + `..._slow.mp3` — 8708 файлов, 173MB. Имя файла = `id` предложения.
- Индекс `C:/Users/mesh/Desktop/hsk30-sentences-index-ru.json` (57MB) — 4354 предложения: `{id, zh, pinyin, en, ru, en_ru, level, glosses_ru[]}`. Покрытие 5346/5354 слов HSK.
- `glosses_ru`/`en`/`en_ru` выбрасываем (57MB → ~1MB): в приложение идут `id, zh, pinyin, ru, level`.
- MP3 в git НЕ коммитим: `hsk_audio/` в `.gitignore`, импорт в хранилище скриптом (как `hanzi-writer-data`).

## 1. Датасет и скрипты (server)
- **`apps/server/scripts/build-sentences-dataset.mjs`** (комитится): читает исходный индекс (путь аргументом), собирает плоский список уникальных предложений `{id, zh, pinyin, ru, level}` → пишет `apps/server/prisma/seeds/hsk-sentences.json` (~1MB, комитится). Запускается один раз.
- **`apps/server/scripts/seed-sentences.ts`** (замена `scripts/seed-examples.ts`):
  - `deleteMany` старых `source in ('tatoeba','hsk_audio')`;
  - для каждого Word: подбор предложений `zh.includes(word.character)`, ранжирование (уровень = уровню слова → ниже → выше, затем короче), кап 6 на слово;
  - `createMany` чанками; поля `chinese, pinyin, russian, source:'hsk_audio', hskLevel, audioUrl, audioSlowUrl` (URL через `resolveStorage().publicUrl('${id}.mp3'|'${id}_slow.mp3')` — детерминированы, работают и для dev, и для GCS).
  - `package.json`: `examples:seed` → новый скрипт (имя сохраняем, как в AGENTS.md).
- **`apps/server/scripts/import-sentence-audio.ts`**: копирует `hsk_audio/**.mp3` (оригинальные имена, плоско) в хранилище через `resolveStorage()` (локальный `AUDIO_STORAGE_PATH` — раздача уже идёт через существующий `GET /audio/files/:fileName`; GCS — прод). Идемпототентно (`exists` → skip), флаги `--dry/--limit`. Скрипт `audio:import-sentences` в package.json.
