## TL;DR (Для людей)

**Что вы получите:** Поэтапную дорожную карту v0.6, которая сначала устраняет критические дефекты (сериализация BigInt, приватность колод, целостность сессий, гонки синхронизации, изоляция аккаунтов), затем hardening клиентов (веб PWA, мобильное офлайн-продолжение, уведомления) и на последней волне добавляет staged-фичи (мобильный паритет практик, тематические колоды, удаление аккаунта, режим рисования иероглифов).

**Почему такой подход:** Сервер остаётся источником истины, каждое офлайн-изменение получает терминальное подтверждение, всё локальное состояние изолировано по аккаунту. Полная офлайн-генерация сессий сознательно отложена до v0.7 — пока не спроектирована серверная sync-архитектура с персистентными курсорами.

**Что НЕ будет сделано:** Повтор закрытых пунктов v0.5, бесшумное удаление данных, раскрытие приватных колод или ответов тестов, Stripe-биллинг, заявления о полном офлайне до того, как сессии реально генерируются локально.

**Трудозатраты:** XL (38 связанных задач через 5 пакетов монорепозитория)
**Риск:** Высокий — пересекаются кросс-платформенные изменения протокола sync, миграции, изоляция аккаунтов и мобильный релизный паритет.

**Принятые за вас решения:** Приоритет — блокеры безопасности и целостности данных; per-user очереди и курсоры; явные исходы каждого sync-изменения (applied/duplicate/stale/rejected); приватные колоды видны только владельцу; неразрушающий preflight миграций (без автоудаления данных); граница v0.7 для полной офлайн-генерации сессий и серверных sync-таблиц.

## Объём (Scope)

### Обязательно (Must have)
- Реализация каждого подтверждённого дефекта (34 finding'а); блокеры релиза — первыми
- **Сервер:** безопасная сериализация BigInt, авторизация на всех word-путях, целостность сессий (membership, completedAt, perfect_session), безопасные таймстемпы (сервер — источник истины), корректные стрики/activity, безопасный сброс данных, неразрушающие миграции
- **Синхронизация:** явные терминальные подтверждения (applied/duplicate/stale/rejected), защита от конкурентных гонок, per-user изоляция очередей/курсоров/прогресса на web и mobile
- **Клиенты:** мобильный production build gate, веб/PWA performance и update hardening, валидация API-контрактов во время выполнения, документация, CI-покрытие тестами
- **Фичи (staged):** мобильный паритет практик (3+4 типа), тематические колоды, удаление аккаунта, push-регистрация, handwriting quiz — каждая фича с явным non-goal, где полный объём отложен

### Запрещено (Must NOT have)
- Редактирование продуктового кода на фазе планирования (это задача воркера)
- Повторная реализация закрытых пунктов v0.5 (24 пункта подтверждены исправленными)
- Бесшумное удаление данных (ни миграции, ни reset, ни schema recovery)
- Раскрытие приватных колод, ответов тестов или reuse чужих офлайн-очередей
- Серверные `SyncCursor`/`SyncChange` таблицы в v0.6 (только документирование границы v0.7)
- Stripe/Pro биллинг или новые внешние sync-вендоры
- Ослабление accessibility, анимаций, аудио или семантики тренировочных режимов ради очков Lighthouse

## Стратегия выполнения (6 волн, 38 задач)

### Wave 0 — Тестовая инфраструктура (задачи 1–6)
Сделать тесты, CI-сервисы, preflight миграций и мобильную сборку исполняемыми.
- Root `test` скрипт + Turbo `test` task
- Server/shared test entry points
- Web jsdom-окружение + storage reset fixtures
- CI: Postgres/Redis service containers + тестовый гейт
- Мобильный production TypeScript build (исправить падающий `build:tsc`)
- Неразрушающий preflight для миграции SessionAnswer unique index

### Wave 1 — Серверный hardening (задачи 7–13)
Убрать блокеры доступности/безопасности/целостности данных.
- Сериализация BigInt → безопасный публичный DTO
- Приватные колоды: один access-хелпер для study-map, words?deckId, sessions.start
- Сессионный membership: проверка wordId, completedAt, perfect_session
- Безопасные таймстемпы: серверный источник истины; client-время только для offline elapsed
- OAuth: атомарный state (GETDEL); revoked-token защита на optional-auth
- Разделение публичного и серверного DTO тестов (correctAnswer — только после submit)
- Безопасный reset и word/deck lifecycle (подтверждение, FK-обработка, документированный скоуп)

### Wave 2 — Sync и изоляция аккаунтов (задачи 14–20)
- Терминальные sync-подтверждения (applied/duplicate/stale/rejected) — каждый вход получает ровно один исход
- CAS/оптимистичная блокировка для конкурентных sync-обновлений
- Per-user очереди/курсоры/прогресс на web и mobile
- Очистка React Query кэша при смене аккаунта; web storage readiness gate
- Мобильный pull-merge через `setOnServerChange` → WatermelonDB
- Bound sync/import payloads; документирование v0.7 границы
- Single-flight mobile refresh/logout (shared promise вместо isRefreshing bail-out)

### Wave 3 — Клиентский hardening (задачи 21–26)
- Сохранение богатого кэша слов (merge вместо перезаписи null'ами)
- Мобильный офлайн-континуацию: кэш слов/прогресса из сессии, точный FSRS elapsed
- Коррекция streak/activity (live-ответы обновляют активность; дашборд — нет; негативные timezone-окна)
- Timezone/frequency-aware push-уведомления + rollback подписки при сбое
- Безопасный и доступный reset UX (разделение local/remote, модальное подтверждение)
- PWA budget: runtime-cache для handwriting JSON, route-level code-splitting, skipWaiting/clientsClaim, SPA navigation fallback

### Wave 4 — Staged product-фичи (задачи 27–34)
- Мобильное аудио, аналитика и response-time паритет
- Порт 3+4 практик (multiple-choice, reverse-choice, pinyin-input + tone, syllable, cloze, character assembly)
- Мобильные decks/reading/stats/settings с валидацией общих схем
- Тематические колоды (еда, транспорт, бизнес, идиомы) — идемпотентный seed
- Handwriting quiz (захват/оценка штрихов) или честное переименование демо
- Удаление аккаунта (реаутентификация, typed-подтверждение, каскадная очистка) + OAuth-линковка
- Документирование границы v0.7: модель SyncCursor/SyncChange, tombstones, conflict-политика

### Wave 5 — Контракты, тесты, observability (задачи 35–38)
- Синхронизация response-схем и API-спецификации (activity, record-answer, sync, devices)
- Regression-тесты на каждый blocker F01–F18 + route/service тесты для непокрытых модулей
- Observability: request correlation id, structured cron/analytics-логи, sync-метрики
- Docker: Trivy-скан, SBOM, cosign-подпись; publish только после тестов
- Кросс-платформенные FSRS golden vectors (server = web = mobile-sdk) с late-elapsed покрытием

## Стратегия коммитов
- Один атомарный коммит на поведенческую задачу; реализация и её прямые тесты — вместе
- Изменения server/shared схем и миграций — только когда миграция требует контракта
- CI/docs/PWA изменения — отдельно от логики обучения
- Никогда не коммитить `dist/`, скопированные handwriting-данные, `.omo/evidence/`, секреты, локальные логи
- Стиль коммитов: `fix(server): ...`, `fix(sync): ...`, `feat(mobile): ...`, `test(ci): ...`, `docs(api): ...`

## Критерии успеха
- Каждый блокер F01–F11 имеет регрессионный тест и проходит в изолированном CI с Postgres/Redis
- Каждый sync-вход получает терминальный ack; дубликаты/stale/чужие изменения не остаются в pending
- Ни одной утечки приватных колод, ответов тестов, прогресса по revoked-токену или BigInt-ответа
- Live и офлайн-учёба обновляют стрик/сессию/достижения консистентно
- Веб и мобильная production-сборка проходят; PWA precache/update бюджет осознан
- v0.6 фичи достижимы, задокументированы и протестированы без претензий на отложенную полную офлайн-генерацию сессий
